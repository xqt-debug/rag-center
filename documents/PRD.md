# RAG Center 产品需求文档（PRD）

- 版本：v0.2
- 日期：2026-11-13
- 状态：计划阶段，供产品与开发评审
- 核心技术约束：主要使用 Python、PostgreSQL

## 1. 产品定位

RAG Center 是面向个人 Agent 的多用户知识检索平台。用户登录后上传资料、管理知识库，通过网页验证检索效果，并创建密钥、生成 MCP 客户端配置，让自己的 Agent 对授权知识库和文件执行完整增删改查及检索。

平台负责资料处理、检索、来源追溯和权限控制；回答生成由用户自己的 Agent 完成。第一版不要求用户向平台提供聊天模型密钥。

## 2. 需求依据与规划边界

### 2.1 已确认需求

1. 支持用户登录，优先采用手机号登录。
2. 同时支持向量搜索和关键词搜索。
3. 前端支持登录、上传和下载文件。
4. 用户可以创建访问密钥。
5. 前端可以生成用于接入 MCP 的 JSON 配置。
6. 用户自己的 Agent 通过 MCP 使用搜索能力，并对知识库和文件执行完整增删改查。
7. 后端主要使用 Python，数据库使用 PostgreSQL。

### 2.2 本文建议的第一版基线

以下是用于使需求可实施、可验收的规划建议，尚未构成用户对具体供应商或实现方式的最终选择：

- 账号密码登录，提供独立注册入口。
- 知识库用于组织文件和定义密钥访问范围。
- 提供向量、关键词、混合三种检索模式，默认混合检索。
- 文件解析与索引由后台任务执行，支持状态展示和失败重试。
- 第一版支持 TXT、Markdown、可提取文本的 PDF。
- MCP 首批适配支持远程 HTTP 与自定义认证请求头的客户端。
- 文件删除、密钥撤销、跨用户隔离属于第一版必备能力。

## 3. 目标用户与核心场景

### 3.1 目标用户

拥有自己的 Agent，希望将私人文档接入其工作流的个人用户。第一版以个人知识库为主，不引入团队共享和组织权限。

### 3.2 核心流程

手机号登录 → 创建知识库 → 上传文件 → 等待索引完成 → 网页测试检索 → 创建密钥并选择知识库范围及操作权限 → 生成 MCP JSON → 配置自己的 Agent → 创建、读取、更新、删除知识库与文件，并检索资料。

### 3.3 产品目标

- 用户可以独立完成从上传资料到 Agent 检索的完整流程。
- 向量和关键词检索均可独立使用，混合检索可以综合两者结果。
- 搜索结果包含来源定位，便于 Agent 引用和用户核对。
- 用户仅能访问自己的资料，Agent 仅能访问密钥授权的资料。
- Agent 可以通过 MCP 完成知识库和文件管理闭环，包括文件上传下载、内容更新和删除。
- 文件处理失败可发现、可诊断、可重试。

## 4. 第一版范围

| 模块 | 第一版能力 |
| --- | --- |
| 用户账户 | 账号密码登录、自主注册、退出登录 |
| 知识库 | 创建、列表、改名、删除 |
| 文件管理 | 上传、列表与详情、改名、内容更新／替换、处理状态、下载原文件、删除、失败重试 |
| 检索 | 向量、关键词、混合检索；知识库范围过滤；来源展示 |
| 密钥管理 | 创建、命名、限制知识库范围与操作权限、可选过期时间、撤销 |
| MCP 接入 | 知识库与文件完整增删改查、上传下载、处理状态与重试、搜索、片段展开、客户端配置生成 |
| 运行管理 | 任务持久化、失败记录、基本调用日志与资源限额 |

### 4.1 暂不包含

- 平台内完整聊天与自主 Agent 执行能力。
- 扫描 PDF 的 OCR、图片检索、音视频解析、复杂表格理解。
- DOCX、PPTX、XLSX 等额外文件格式。
- 团队协作、公共知识库、跨用户分享。
- 网站抓取、网盘同步和其他外部数据源连接。
- 计费套餐、复杂配额策略、多模型市场、自动选择 Embedding 模型。
- 任意 MCP 客户端的通用兼容承诺。

## 5. 页面与交互需求

### 5.1 登录与注册页

- 所有环境仅支持账号密码登录，提供独立注册入口，注册后直接进入知识库。
- 账号为 1–64 位字母、数字、下划线、点或短横线，以字母或数字开头，区分大小写；密码为 8–256 位，注册时确认密码。
- 重复账号、无效输入、密码错误与频率限制显示明确提示。登录失败不创建账户。
- 密码使用随机盐 scrypt 哈希保存，不返回或记录密码。
- 登录成功保持会话，网页写请求校验 CSRF；退出后原会话失效。
- 对账号、IP 的登录尝试和 IP 注册频率限流；移除短信验证码和固定开发账号入口。

### 5.2 知识库页面

- 展示当前用户的知识库名称、文件数量和创建时间。
- 支持创建、改名和删除知识库，名称为空时不可提交。
- 删除知识库前提示影响范围并确认；删除后其内容立即退出检索。
- 删除操作同步移除密钥对该知识库的授权关系。

### 5.3 文件管理页面

- 在指定知识库中选择文件上传，展示上传进度。
- 文件列表展示名称、类型、大小、上传时间和处理状态。
- 区分文件保存成功与索引完成，解析失败不得显示为可检索。
- 支持下载当前用户的原文件，即使该文件索引失败。
- 支持修改文件显示名称；仅改名不触发内容重建索引。
- 支持上传新内容替换指定文件，保留稳定文档 ID，创建新文档版本并重建两个索引。
- TXT、Markdown 支持读取和编辑完整文本，采用分页或分段读取并设置单次返回上限；PDF 通过上传新文件替换内容。
- 失败项展示可理解的原因与重试入口，不展示密钥、内部路径或供应商原始响应。
- 支持删除文件；删除后立即从检索和下载入口隐藏，底层数据允许异步清理。
- 第一版同名文件作为独立文件处理，不静默覆盖；后台重试不得产生重复索引。
- 文件大小、数量、存储空间和允许类型均有可配置上限，上传前后都需校验。
- 不支持或无法处理的文件明确提示，不能静默跳过后显示成功。

### 5.4 搜索测试页面

- 用户可选择一个或多个知识库，默认搜索自己全部可访问知识库。
- 支持输入查询、选择向量／关键词／混合模式、设置有限范围内的结果数量。
- 每条结果展示文本片段、文件名和可用的页码／章节定位。
- 支持展开相邻文本，必要时进入授权的原文件下载入口。
- 空查询、没有可检索文件、无结果和服务失败分别展示对应状态。
- 该页面与 MCP 共用检索服务和权限规则。
- 如展示排名分数，须说明其属于检索相关性分数，不表示答案正确概率。

### 5.5 密钥管理与 MCP 接入页面

- 创建密钥时填写名称，选择可访问知识库、操作权限，并可设置过期时间。
- 第一版密钥范围采用明确的知识库列表；用户通过网页或其他密钥新增知识库，不会自动扩大已有密钥权限。
- 提供“只读检索”和“完整管理”权限模板，同时允许分别选择读取、创建、修改、删除与原文件下载权限；默认选中只读模板，用户可直接选择完整管理。
- 单独提供“允许创建知识库”权限；仅创建用途的密钥允许初始知识库列表为空。
- 密钥经授权创建的新知识库自动加入该密钥自身的访问列表，并继承其已有的操作权限；其他密钥不自动获得访问权。
- 创建页面清楚展示将授予 Agent 的管理范围，完整管理模板包含知识库创建及授权范围内文件上传、内容更新、下载和删除。
- 完整密钥仅在创建成功时展示一次，支持复制，并提醒妥善保存。
- 列表仅展示密钥名称、可辨认前缀、权限范围、创建时间、到期时间、最近使用时间和状态。
- 支持撤销；服务端确认撤销后，后续请求立即拒绝。
- 用户选择支持的客户端类型后，系统生成对应格式的配置，支持复制和下载 JSON。
- 创建密钥的当前流程可直接生成含密钥的配置；离开后重新生成仅提供占位符，或由用户手动填入已有密钥。
- 含密钥配置不写入服务日志，不提供长期公开下载链接；页面刷新后不可恢复完整密钥。
- 未适配客户端提供连接地址、认证方式和手动配置说明，不标记为已验证兼容。

## 6. 文件处理与数据生命周期

### 6.1 处理流程

保存原文件 → 创建持久化任务 → 提取文本 → 分块与记录来源 → 建立关键词索引与向量索引 → 标记可检索。

建议状态：`queued`、`parsing`、`chunking`、`indexing`、`ready`、`failed`、`deleting`。

- `ready` 表示两个检索索引均可用。
- 无可提取文本的 PDF 应提示需要 OCR，第一版不自动处理。
- 后台任务进程重启后可以恢复未完成任务，避免任务永久停留在处理中。
- 对可恢复的供应商错误采用有限重试；超过限制后标记失败并允许手动重试。
- 相同任务重复执行不得产生重复文本块，旧任务不得恢复已删除文件。
- 仅发布完整索引版本，处理中间结果不进入正常检索。

### 6.2 来源与版本

- 原文件、提取文本、文本块和索引建立明确关联。
- 文本块记录文档版本、序号、标题、页码／章节及必要的文本偏移。
- PDF 优先记录原文件物理页码；其他格式记录可用的行号或章节，不虚构页码。
- 记录内容摘要、解析器版本、分块配置和 Embedding 模型、维度。
- 更换 Embedding 模型时需重建相应索引，不允许混用不兼容的向量空间。
- 原文件和数据库分别持久化，部署与备份方案需覆盖两者。

### 6.3 内容更新与并发

- 文档具有稳定 ID；内容更新创建新版本，原文件与索引均关联相应版本。
- 新版本两个索引就绪后，原文件、文本读取与检索的当前版本原子切换；处理期间旧版本继续可用，并明确展示更新中。
- 新版本处理失败时保留旧版本可用，允许查看失败原因并重试；尚无成功版本的新文件保持不可检索。
- 版本切换后，旧版本片段请求返回版本已更新信息，调用方重新检索；第一版不提供历史版本浏览与回滚。
- 更新请求带预期修订号；并发覆盖返回冲突，调用方读取最新状态后重新提交。
- 删除优先于更新任务发布，迟到任务不得将已删除文档重新上线。

## 7. 检索需求

### 7.1 模式

| 模式 | 行为 |
| --- | --- |
| `semantic` | 查询向量化后执行语义检索 |
| `keyword` | 对查询执行分词与关键词检索，不依赖查询 Embedding 调用 |
| `hybrid` | 两路检索分别召回候选结果，再进行排名融合 |

### 7.2 混合检索规则

- 建议以 RRF 作为第一版融合算法，不直接相加不同尺度的原始分数。
- 两路检索均在有效用户和密钥授权范围内执行。
- 查询端与文档端使用一致的中文分词和词项规范化规则。
- 为英文缩写、编号、型号等精确查询准备专门的评估样例。
- 融合后按文本块标识去重，并控制单文档重复片段数量。
- 返回结果数量与总文本长度均设上限，防止耗尽 Agent 上下文。
- 没有命中时返回空列表，不将无关内容包装成答案。
- 混合检索一路失败时可返回另一路结果，但必须明确标注降级原因；两路均失败则返回错误。
- 近似向量检索需在知识库与用户过滤条件下验证召回，不能只测试无过滤查询。

### 7.3 返回信息

每条结果至少包括：文本块 ID、文档 ID、文档版本、知识库 ID、文件名、文本内容、可用来源定位和引用描述。原始排名分数为可选诊断字段。

## 8. MCP 接口与配置

### 8.1 工具范围

MCP 必须提供知识库与文件的完整增删改查，以下工具均属于第一版范围。工具命名与具体参数可在技术设计中调整，但不得缩减对应能力。

| 资源 | 工具 | 行为 |
| --- | --- | --- |
| 知识库 | `create_knowledge_base` | 创建知识库并返回 ID，将其加入当前密钥范围；要求知识库创建权限 |
| 知识库 | `list_knowledge_bases` | 分页列出密钥可读的有效知识库 |
| 知识库 | `get_knowledge_base` | 获取名称、描述、文件数量及修订号等详情 |
| 知识库 | `update_knowledge_base` | 修改名称、描述，校验预期修订号 |
| 知识库 | `delete_knowledge_base` | 删除知识库及所含文件的可见性，返回受影响文件数和清理状态 |
| 文件 | `create_document` | 从 TXT／Markdown 文本或已完成的上传对象创建文件，返回文档 ID 与任务 ID |
| 文件 | `list_documents` | 在授权知识库内分页列出文件，可按名称、处理状态筛选 |
| 文件 | `get_document` | 获取文件元数据、当前版本、最新处理状态与修订号 |
| 文件 | `read_document` | 分段读取当前版本文本，返回来源与继续读取游标；PDF 读取提取文本 |
| 文件 | `update_document` | 修改显示名称，或以 TXT／Markdown 文本、已完成上传对象替换内容；校验预期修订号 |
| 文件 | `delete_document` | 删除文件，使其立即退出列表、读取、下载和检索 |
| 文件传输 | `prepare_document_upload` | 为创建或替换内容签发短期上传会话，限定知识库、文件类型、大小及替换目标 |
| 文件传输 | `download_document` | 获取经授权的当前原文件下载地址及有效期，不将大文件编码进工具文本 |
| 处理任务 | `get_ingestion_job` | 查询当前密钥可读文件的处理阶段和可展示失败原因 |
| 处理任务 | `retry_document_processing` | 对授权文件重试失败的处理版本，要求修改权限 |
| 检索 | `search` | 使用 `query`、`knowledge_base_ids?`、`mode?`、`limit?` 检索，默认混合模式 |
| 片段 | `get_document_excerpt` | 按 `document_id`、`chunk_id` 展开上下文，校验当前版本、所属关系和返回上限 |

- 省略知识库参数时，搜索密钥授权的全部有效知识库。
- 显式传入未授权知识库时拒绝请求，不静默扩大或改变范围。
- 身份从凭证确定，工具参数不接受用来切换身份的 `user_id`。
- 返回的文档文本作为资料数据处理，平台不将其中指令提升为系统指令。
- 同一查询在同样身份、权限和参数下，网页与 MCP 应有一致检索行为。
- 账户登录、手机号变更和密钥签发由网页管理；本文所指完整增删改查对象为知识库与文件。
- 文本块与向量是文件内容的派生数据，不作为独立可编辑资源；修改原文后统一重建索引。

### 8.2 传输、认证与兼容性

- 远程 MCP 建议使用 Streamable HTTP，生产环境通过 HTTPS 提供服务。
- 第一阶段适配允许配置认证请求头的客户端，使用独立访问密钥。
- 客户端若仅支持标准 OAuth 授权流程，须另行接入授权服务后才能标记支持。
- MCP 协议不统一客户端本地配置 JSON，平台应按客户端模板生成，并维护实际验证记录。
- 上线前至少选择一个真实客户端验证连接、鉴权、知识库与文件增删改查、上传下载、搜索与片段读取。

以下仅为支持相应字段的客户端配置示意，不作为全部客户端的统一格式：

```json
{
  "mcpServers": {
    "rag-center": {
      "url": "https://rag.example.com/mcp",
      "headers": {
        "Authorization": "Bearer <YOUR_API_KEY>"
      }
    }
  }
}
```

### 8.3 文件传输与异步结果

- 远程 MCP 服务无法直接读取 Agent 所在机器的本地路径；工具不接受把本地路径当作已上传文件。
- 小型 TXT／Markdown 可直接传入文本创建或更新，内容大小上限由服务端配置。
- PDF 或其他较大文件使用上传会话：调用 `prepare_document_upload` → Agent 的 HTTP 文件传输能力上传字节 → 调用 `create_document` 或 `update_document` 提交上传对象 ID。
- 上传对象须绑定用户、密钥、知识库和用途，替换时还须绑定目标文档；提交时再次校验权限、过期时间、实际类型、大小与完整性。
- 提交成功后消费上传对象，重复提交按幂等规则返回同一结果；未提交对象到期清理。
- Agent 必须具备对应 HTTP 文件传输能力才能完成二进制上传下载；仅能调用 MCP 工具的客户端仍可直接创建、读取和修改小型文本文件。
- 第一版不通过任意外部 URL 抓取文件，也不将大文件 Base64 作为主要传输方式。
- 创建、内容替换和重试处理返回任务 ID 与状态；工具调用不阻塞等待全部向量化完成。
- 下载返回的链接必须有明确有效期，完整下载内容应与对应当前版本原文件一致。

### 8.4 写入语义与权限

- 每次调用均同时检查有效密钥、知识库范围及具体操作权限；拥有读取权限不意味着拥有写入权限。
- 知识库创建是账户级权限；对已有知识库的读取、创建文件、修改、删除和下载均受明确范围限制。
- 删除知识库需要知识库删除权限及对其中内容的删除授权，不允许借级联删除绕过文件删除权限。
- MCP 写入在密钥授权范围内直接执行，不依赖网页逐次确认；工具说明必须明确内容替换与级联删除的影响。
- 创建、内容替换、重试与删除支持请求幂等标识；同一标识及相同请求重放返回相同结果，不同请求复用标识返回冲突。
- 幂等结果只在重新通过当前权限和密钥有效性检查后返回，不允许绕过撤销或删除后的访问限制。
- 并发修改、无权限、参数错误、过期上传对象、限流、资源不存在和处理失败返回可区分的错误类型，避免 Agent 盲目重试。
- 删除接口逻辑删除成功后立即生效；物理清理可异步执行，并返回清理状态。
- 写操作记录密钥标识、操作类型、目标资源、时间和结果，不记录密钥明文与文件正文。

## 9. 身份、权限与资源控制

- 网页会话和 MCP 密钥分别管理、分别撤销；退出网页不自动撤销 Agent 密钥。
- 网页建议使用服务端可撤销会话与 `HttpOnly`、`Secure` Cookie，并配置适当的 SameSite 和 CSRF 防护。
- 手机号绑定稳定用户 ID，业务关联不直接依赖手机号。
- 密钥使用高强度随机值，数据库只保存验证摘要与辨认前缀。
- 每次知识库和文件的创建、读取、修改、删除、搜索、上传与下载均在服务端检查归属、范围和操作权限。
- 使用他人文档 ID、文本块 ID 或文件地址不得绕过权限；错误提示避免泄露他人资料是否存在。
- 对象存储保持私有；下载通过鉴权后的后端或短期授权链接完成。
- 对登录、注册、上传、写入、搜索和文本读取设置适当限流与资源上限，网页与 MCP 共用账户存储及任务配额。
- 文件类型、大小、解析时长与资源消耗均受限制；上传文件不作为可执行内容运行。
- 不记录完整密钥、密码和登录令牌；默认不在运行日志中记录原始文档内容。
- 记录必要的操作结果、任务耗时、调用耗时与供应商用量，便于排错和成本观察。

## 10. 建议技术架构

| 部分 | 建议 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript | 具体 UI 组件库待选 |
| Web API | FastAPI | 用户、文件、密钥与调试接口 |
| 数据访问 | SQLAlchemy + Alembic | 模型与数据库迁移 |
| 数据库 | PostgreSQL + pgvector | 业务数据、文本、关键词索引与向量 |
| 后台任务 | 独立 Python worker | 任务持久化，具体队列方案待选 |
| 临时状态 | Redis（建议） | 限流；是否承担任务队列待选 |
| 原文件 | 本地存储适配器／私有对象存储 | 开发与部署环境使用同一抽象接口 |
| MCP | 官方 Python SDK | 共用检索与权限服务 |
| 密码认证与 Embedding | 可替换供应商适配层 | 供应商凭证由服务端管理 |

采用模块化单体作为第一版结构，API 和 worker 可分进程部署。网页接口和 MCP 作为接入层，共用知识库、文件、检索和授权逻辑。

## 11. 核心数据实体

| 实体 | 主要用途 |
| --- | --- |
| `users` | 稳定用户 ID、手机号、账户状态 |
| `sessions` | 网页会话、失效时间与撤销信息 |
| `knowledge_bases` | 用户归属、名称和生命周期 |
| `documents` | 原文件标识、所属知识库、存储位置、大小和状态 |
| `document_versions` | 内容摘要、处理配置、当前可检索版本 |
| `chunks` | 文本、来源位置、关键词索引与向量关联 |
| `ingestion_jobs` | 任务阶段、尝试次数、可展示错误和恢复信息 |
| `api_keys` | 密钥摘要、名称、前缀、操作权限、知识库创建权限、过期与撤销信息 |
| `api_key_knowledge_bases` | 密钥获准访问的明确知识库集合，包括其自行创建的知识库 |
| `upload_sessions` | 上传对象归属、目标、用途、限制、过期与消费状态 |
| `operation_requests` | 写入幂等标识、请求摘要、资源及执行结果 |
| `audit_events` | 写入主体、操作、目标、时间与结果 |

登录限流等短期信息可存入具有 TTL 的临时存储。具体表结构、索引和事务边界在技术设计中确定。

## 12. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 账号认证 | 注册并登录成功；重复账号、弱密码、错误密码被拒绝；退出会话失效 |
| A02 | 会话退出 | 退出后原会话不能访问受保护接口 |
| A03 | 知识库管理 | 用户可创建、改名和删除自己的知识库，无法操作他人的知识库 |
| A04 | 上传与下载 | 支持格式可上传并下载原文件；下载内容与上传内容一致 |
| A05 | 异步处理 | 前端显示处理阶段；两个索引完成后文件才进入正常检索 |
| A06 | 失败与恢复 | 失败原因可见；重试与 worker 重启恢复不产生重复文本块 |
| A07 | 三种检索模式 | 向量、关键词、混合均能独立执行，并通过预先标注的语义与精确词项样例 |
| A08 | 来源定位 | 结果能追溯到原文档和可核对的位置；片段展开匹配所属文档 |
| A09 | 数据隔离 | 用户 A 无法通过列表、搜索、片段读取或下载访问用户 B 数据 |
| A10 | 密钥范围 | 仅授权知识库可访问；网页或其他密钥新建的知识库不自动加入当前密钥范围；当前密钥获准自行创建的知识库加入其自身范围 |
| A11 | 密钥生命周期 | 完整密钥仅创建时可见；过期或撤销后后续请求被拒绝 |
| A12 | MCP 配置 | 配置 JSON 可解析，并在至少一个明确版本的真实客户端完成连接、鉴权和完整管理流程 |
| A13 | 删除生效 | 文件或知识库删除后，后续检索、展开与新下载请求不可访问；正在运行的任务不能恢复其可见性 |
| A14 | 无结果与降级 | 无命中返回空列表；单路故障有明确降级标志；双路故障返回可理解错误 |
| A15 | 敏感信息 | 日志不含完整密钥、密码、登录令牌或供应商凭证 |
| A16 | MCP 知识库 CRUD | Agent 可创建、分页列出、读取、更新和删除授权知识库；删除后范围关系和内容可见性同步失效 |
| A17 | MCP 文件 CRUD | Agent 可创建、列出、读取、改名、替换内容、下载和删除文件；支持文本直传及上传会话路径 |
| A18 | 内容一致性 | 仅改名不重建索引；内容更新成功后原文件、文本读取和两类索引切换到同一版本，旧片段明确提示失效；更新失败旧版本可用 |
| A19 | 操作权限 | 只读密钥不能创建、更新、重试或删除；下载按独立权限控制；授权管理密钥可完成全部 CRUD；越权请求不产生副作用 |
| A20 | 幂等与并发 | 相同请求重放不重复创建文档或任务；幂等标识冲突与过期修订号返回冲突；删除期间迟到任务不能重新发布 |
| A21 | 上传与下载 | 跨用户、跨密钥或跨目标上传对象、过期对象被拒绝；下载受授权与有效期约束，字节内容与版本一致 |
| A22 | 任务与审计 | Agent 可查询和重试获授权任务，不能查询他人任务；写入有不含凭证明文和正文的审计记录 |

已签发的短期下载链接在有效期内可能继续可用；若要求删除后立即阻止所有下载，应采用每次请求均鉴权的后端下载方案，并在技术设计时明确选择。

## 13. 实施阶段建议

1. 确定关键依赖：账号规则、Embedding 服务、目标 MCP 客户端和部署环境。
2. 建立账户与资料闭环：登录、知识库、上传、下载、权限隔离。
3. 建立处理与检索闭环：持久化任务、解析分块、两类索引、三种检索模式和调试页面。
4. 建立 Agent 接入闭环：密钥范围与操作权限、MCP 完整增删改查、上传下载、版本切换与幂等、配置生成、真实客户端验证。
5. 完成上线验证：恢复与删除、限流与配额、检索评估、备份及成本观察。
